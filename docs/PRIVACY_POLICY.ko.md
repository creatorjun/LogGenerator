# LogGenerator 개인정보처리방침

상태: 게시 전 초안. 운영자가 아래 미등록 항목과 실제 배포 환경을 확정한 뒤 공개 HTTPS 웹페이지로 게시해야 합니다. 게시 URL은 `StoreConfig.local.psd1`의 `PrivacyPolicyUrl`과 Partner Center에 입력합니다. 제출 빌드에서는 앱의 `개인정보 안내`에 있는 `온라인 개인정보처리방침` 버튼으로 해당 페이지를 엽니다. 개발 검증 빌드는 URL 없이 로컬 안내만 제공할 수 있습니다.

| 항목 | 값 |
| --- | --- |
| 앱 이름 | LogGenerator |
| 개인정보처리자 / 운영자 | 미등록 — 실제 회사 또는 배포 주체 입력 필요 |
| 개인정보 문의 연락처 | 미등록 — 실제 담당 부서 및 이메일 입력 필요 |
| 공개 개인정보처리방침 URL | 미등록 — 실제 HTTPS 게시 주소 입력 필요 |
| 시행일 | 미등록 — 실제 시행일 입력 필요 |
| 문서 검토 기준일 | 2026-09-11 |

LogGenerator는 사용자가 선택하거나 작성한 샘플 로그를 바탕으로 테스트 이벤트를 생성하여 로컬 파일 또는 지정한 수신기로 출력하는 데스크톱 프로그램입니다.

## 처리하는 정보와 목적

앱은 샘플 로그 편집과 생성에 필요한 내용을 이 컴퓨터에서 처리합니다. 여기에는 직접 입력한 로그, 선택한 CSV 파일 내용, 샘플 이름·출처, 테스트 값, 전송 대상 호스트·포트, 생성할 IP 및 시각 설정이 포함됩니다. 입력에 이름, 계정, 이메일, IP, 경로 등 개인을 식별할 수 있는 정보가 있으면 처리 내용에도 포함될 수 있습니다.

카탈로그 저장과 로그 생성 과정에서 일부 개인정보 패턴을 토큰이나 합성 값으로 바꾸는 기능을 제공합니다. 모든 입력 형식이나 샘플 이름·출처·파일 이름까지 익명화하는 것을 보장하지 않습니다. 실제 개인정보나 기밀값 대신 검토한 합성 테스트 데이터를 사용해 주세요.

앱의 진단 로그에는 실행 시각, 작업 상태, 전송 대상 호스트·포트, 파일 경로, 처리 건수, 오류 등이 기록될 수 있습니다. 이는 실행 상태 확인과 문제 진단에 사용됩니다. 파일 경로에 Windows 계정명이나 업무 정보가 포함될 수 있습니다.

## 저장과 보유

Store/MSIX 실행에서는 샘플 카탈로그, 생성한 FILE 결과와 진단 로그가 `%LOCALAPPDATA%\Packages\<PackageFamilyName>\LocalState` 아래에 저장됩니다. 각각 `Sample Logs`, `generated`, `logs` 폴더를 사용합니다. 일반 portable 실행에서는 실행 파일 옆 저장 경로를 사용하며, CLI에서 별도 경로를 지정하면 그 경로를 사용합니다. 사용자가 선택한 원본 CSV 파일은 별도 원본으로 남으며 가져오기 기능이 원본을 삭제하지 않습니다. 카탈로그에는 가져온 샘플과 출처 파일 이름이 저장될 수 있습니다.

앱에는 날짜가 지난 데이터를 자동 파기하는 보존 기간 설정이 없습니다. 사용자가 카탈로그를 수정하거나 파일을 삭제할 때까지 보관될 수 있습니다. 생성한 파일이나 복사·백업한 파일은 앱 제거만으로 모두 삭제되지 않을 수 있습니다. 회사의 보관 정책에 따라 필요한 파일을 관리해 주세요.

현재 카탈로그와 진단 로그, FILE 결과는 앱 자체에서 암호화하여 저장하지 않습니다. 컴퓨터의 계정 권한과 조직이 설정한 저장 장치 보호 정책이 적용됩니다.

## 네트워크 전송과 수신자

사용자가 UDP, TCP 또는 TLS 모드에서 전송을 시작하면 앱이 생성한 이벤트를 사용자가 지정한 호스트·포트로 보냅니다. 수신자는 해당 서버를 운영하는 주체입니다. 수신 서버의 보관·이용·삭제 정책은 그 운영자가 정합니다. 호스트 이름을 입력한 경우 Windows의 이름 해석 과정에서 시스템에 설정된 DNS 서비스를 사용할 수 있습니다.

UDP와 일반 TCP는 로그 내용을 암호화하지 않습니다. TLS는 전송 구간을 암호화하며 서버 인증서 검증 설정을 제공합니다. 서버 인증서 검증을 끄면 연결 대상의 신뢰를 검증하지 못합니다. FILE 모드는 이벤트를 로컬 파일로 출력합니다.

현재 앱 코드에는 앱 운영자에게 자동으로 사용 통계나 로그를 보내는 분석 기능, 광고 SDK, 별도 클라우드 계정 서비스가 없습니다. 사용자가 수신기로 운영자 서버를 직접 지정하거나 진단 자료를 운영자에게 제공하면 해당 자료가 운영자에게 전달될 수 있습니다. 앱 다운로드·업데이트 과정에서 Microsoft Store와 Windows가 처리하는 정보에는 각 서비스의 정책이 적용됩니다.

## 사용자의 선택과 삭제

사용자는 전송할 샘플과 수신기, 프로토콜을 선택하고 전송을 시작하거나 중단할 수 있습니다. 입력한 샘플을 편집·삭제하고 카탈로그를 저장할 수 있습니다. 로컬 데이터의 열람·복사는 해당 파일을 통해 가능하며, 삭제하려면 앱을 종료하고 대상 카탈로그·생성 파일·진단 로그를 삭제할 수 있습니다. Store/MSIX 배포에는 샘플 로그가 포함되지 않으며, 카탈로그 파일을 삭제하면 다음 실행 시 빈 카탈로그가 다시 준비됩니다. 일반 portable 배포에서는 해당 배포에 포함된 카탈로그가 다시 준비될 수 있습니다.

앱에서 전송을 중단하거나 로컬 파일을 삭제해도 이미 수신기로 보낸 자료까지 회수하지는 못합니다. 수신 서버에 저장된 자료의 열람·정정·삭제가 필요하면 그 서버의 운영자에게 요청해 주세요. 문의 목적으로 진단 로그를 보낼 때에는 사용자 경로, 서버 주소와 불필요한 개인정보를 먼저 확인해 주세요.

## 문의와 변경

개인정보 관련 요청은 위에 기입한 실제 운영자의 연락처로 접수합니다. 운영자는 앱 기능이나 데이터 처리 방식이 변경되면 이 방침과 시행일을 갱신하고 배포 중인 버전의 동작을 반영합니다.
